# check_freshness

데이터가 늘어야 할 때 늘었는지 본다.

## 왜 있나

명령이 실패하면 종료코드로 알린다([commands.md](./commands.md) 의 '실패를
알리는 방식'). 그런데 그것으로 못 잡는 고장이 따로 있다 — **명령은
성공했는데 입력이 썩은 경우**다.

시장 수급이 석 달 끊긴 동안 `save_market_indicator` 는 외인 20일 누적을
엉터리로 계산하면서 날마다 '완료' 를 찍었다. 자기 할 일은 다 했기 때문이다.
성공·실패가 아니라 신선도의 문제다.

## 사용법

```bash
python manage.py check_freshness            # 표까지 보기
python manage.py check_freshness --quiet    # 문제 있을 때만 (배치용)
python manage.py check_freshness --date 2026-11-20   # 날짜를 가정해 시험
```

## 옵션

| 옵션 | 필수 | 설명 |
|------|------|------|
| `--date` | X | 오늘 대신 이 날짜 기준 (YYYY-MM-DD). 시험용 |
| `--quiet` | X | 문제가 있을 때만 출력 |
| `--log-level` | X | debug / info / warning / error (기본: info) |

## 기준일을 어디서 잡나

'오늘 것이 있나' 로 보면 주말·공휴일마다 운다. 그래서 둘을 같이 쓴다.

**① 상대** — 일별 데이터들의 최신일 중 **가장 앞선 것**을 기준 삼아, 거기서
혼자 뒤처진 것을 찾는다.

```
지수 차트  11-13   ← 기준
시장 수급  08-14   ← 61영업일 뒤처짐  ⚠️
일봉       11-13
```

**② 절대** — 그 기준일 자체가 오늘로부터 3영업일 넘게 떨어지면 전체가
멈춘 것이다.

①만 있으면 다 같이 멈췄을 때 못 잡고, ②만 있으면 공휴일마다 운다. 둘이
서로의 구멍을 막는다. 설·추석 연휴가 3영업일을 넘으면 ②가 오경보를 내는데,
1년에 한두 번이고 그때 한 번 들여다보는 것은 나쁘지 않다.

영업일은 평일로만 센다 — 공휴일표가 없다. 실제보다 크게 나오므로 경보가
조금 이르게 울린다. 늦게 우는 것보다 낫다.

## 무엇을 보는지

`stocks/freshness.py` 한 곳에 적혀 있다 — `CHECKS`(신선도), `GAPS`(정체),
`CROSSES`(교차 검증).

### ① 신선도 (`CHECKS`)

거래일마다 늘어야 하는 것. '모든 데이터가 오늘
것이어야 한다' 로 짜면 틀리기 때문에 일일이 선언한다.

```
지수 차트 · 시장 수급 · 시장 지표 · 일봉 · ETF 일봉 · 업종
종목 수급 · 공매도 · 계좌 스냅샷 · 매매일지
```

`group` 을 준 항목(지수 차트·시장 수급·시장 지표)은 코스피/코스닥을 따로
본다. 합쳐서 보면 한쪽만 빠진 것이 가려진다.

### ② 정체 (`GAPS`)

부정기 데이터는 거래일마다 늘지 않아 ①의 방식으로 볼 수 없다. 달력일로
센다.

| 항목 | 한도 | 근거 |
|---|---|---|
| 공시 | 10일 | 최근 120개 날짜의 간격이 중앙 1일, 최대 5일 |
| 리포트 | 10일 | 같음 |
| 재무 | 10일 | 주간 배치. `updated_at` 을 본다 |

재무는 값이 안 바뀐 행을 건드리지 않으므로 종목 하나만 보면 안 된다.
1,249종목 전체에서 가장 최근에 바뀐 것을 본다 — 컨센서스가 움직인 것이
늘 몇 개는 있다.

### ③ 교차 검증 (`CROSSES`)

날짜 칸이 없는 데이터를 보는 유일한 방법이다. `InfoETF` 는 행이 늘지 않고
값만 바뀌는데, 코드가 `updated_at` 은 매번 갱신하면서 `current_price` 는
그대로 두는 바람에 넉 달 동안 겉보기로 멀쩡했다. 차트와 견줬더니 최대
163% 어긋나 있었다 — 그 비교를 옮겼다.

| 항목 | 견주는 것 |
|---|---|
| ETF 대시보드 | `InfoETF.current_price` ↔ `DailyChartETF` 최신 종가 |
| 종목 현재가 | `Info.current_price` ↔ `DailyChart` 최신 종가 (관심종목) |

한두 개가 어긋나는 것은 거래정지처럼 늘 있는 일이라 넘긴다. **30% 넘게**
어긋나야 고장으로 본다 — 수집이 멈추면 하나가 아니라 전부 어긋난다.

**장중(평일 09:00~16:00)에는 건너뛴다.** 현재가와 전일 종가가 다른 것이
당연해서 전부 어긋난 것처럼 보인다. 배치는 저녁에 도니 걸릴 일이 없고,
손으로 낮에 돌렸을 때만 해당한다.

### 일부러 안 보는 것

| | 왜 |
|---|---|
| `MarketDiary` | 사람이 쓰는 투자일기. 몇 달 비어도 정상 |
| `WeeklyChart` `MonthlyChart` | 주·월 단위라 이 방식으로 볼 수 없다 |

## 실행 주기

`evening_update.sh`(평일 19:40) 의 **맨 끝**. 그날 데이터가 다 들어온
뒤라야 뜻이 있다.

```bash
step "신선도 점검" python manage.py check_freshness --quiet --log-level info
```

이상이 있으면 `오류: N개` 와 종료코드 1 로 끝나 `batch_lib.sh` 가 텔레그램을
보낸다. 멀쩡하면 조용히 끝난다 — 날마다 '정상' 을 보내면 그것이 다시
소음이 된다.
